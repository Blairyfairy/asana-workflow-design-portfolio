# Portfolio Overview

## Portfolio name

**Phoenix Airlines Workflow Portfolio** — a practical umbrella for two delivery workflows and one adoption plan.

## Executive summary

This portfolio demonstrates a repeatable method for turning loosely defined work into an observable, governed workflow. The design combines a delivery project for biometric boarding and security improvements with an intake-and-approval workflow for internal project requests. A socialization plan supports the people side of deployment.

## Design principles

1. **Outcome first:** each workflow has a goal and measurable acceptance criteria.
2. **Clear ownership:** every active task has one accountable owner; supporting contributors are added as collaborators.
3. **Small, visible stages:** sections represent meaningful states or phases, not individual people.
4. **Structured data:** custom fields capture information needed for routing, prioritization, risk, and reporting.
5. **Automate predictable work:** rules move work or notify owners when known conditions are met.
6. **Keep decisions explicit:** approvals have an approver, a decision, and a recorded outcome.
7. **Make handoffs observable:** dependencies identify prerequisites and prevent premature starts.
8. **Adopt deliberately:** pilot users, training, communications, and feedback are part of the delivery plan.
9. **Measure responsibly:** targets are proposed until validated against a baseline.
10. **Design for safe exceptions:** blocked, rejected, urgent, and inaccessible paths are documented.

## Roles (role-based examples)

| Role | Primary responsibility |
|---|---|
| Executive sponsor | Confirms business outcome, resolves escalations |
| Workflow owner | Owns process design, conventions, and improvements |
| Project manager | Maintains schedule, dependencies, risks, and milestones |
| Security/privacy lead | Reviews privacy, security, retention, and access controls |
| Request coordinator | Validates intake, routes requests, and maintains request quality |
| Approver | Makes and documents a decision within the agreed service window |
| Pilot champion | Tests the workflow, models usage, and relays feedback |
| Contributor | Completes assigned tasks and keeps status current |

## Recommended Asana setup

- Create a portfolio named **Phoenix Airlines Workflow Portfolio** (or **Phoenix Airlines Workflows**).
- Add the two projects named in the project blueprints.
- Track the socialization plan as a project or a sectioned task project, depending on team needs.
- Use List or Timeline for delivery planning and Board or List for request intake.
- Use portfolio-level status updates and project-level dashboards if available in the workspace plan.
