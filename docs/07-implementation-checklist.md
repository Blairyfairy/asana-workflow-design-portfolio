# Implementation Checklist

Use this checklist while creating the native Asana workspace. Check items only after verifying them in the actual project.

## A. Biometric Boarding and Security Initiative

- [ ] Create project with the correct name.
- [ ] Add it to Phoenix Airlines Workflow Portfolio.
- [ ] Create at least four phase sections.
- [ ] Create the custom fields listed in `biometric_custom_fields.csv`.
- [ ] Select List and/or Timeline view.
- [ ] Import tasks and map columns correctly.
- [ ] Confirm every task has an action verb, clear description, owner, and real due date.
- [ ] Add relevant subtasks to divisible work.
- [ ] Convert the three named milestone tasks to native milestones.
- [ ] Create the dependency links listed in `biometric_dependencies.csv`.
- [ ] Add a measurable goal and confirm it reflects approved project policy.
- [ ] Review privacy, security, accessibility, legal, and human fallback gates.
- [ ] Add project to portfolio and confirm reporting visibility.

## B. Phoenix Airlines Project Request

- [ ] Create project and add it to the portfolio.
- [ ] Create the workflow sections.
- [ ] Create custom fields from `request_custom_fields.csv`.
- [ ] Select Board and/or List view.
- [ ] Configure the request form from `request_form_schema.json`.
- [ ] Implement and test branch conditions.
- [ ] Configure approvals and decision recording.
- [ ] Configure rules from `request_rules.csv`.
- [ ] Test complete, incomplete, critical, funding-required, approved, declined, and overdue paths.
- [ ] Define and publish the goal and KPI measurement method.
- [ ] Add project to portfolio.

## C. Socialization and change management

- [ ] Name the workflow owner and change lead.
- [ ] Select a cross-functional pilot cohort using `pilot_members.csv`.
- [ ] Confirm participants' time and accessibility needs.
- [ ] Publish communication plan and owner for each message.
- [ ] Schedule the two-week training plan.
- [ ] Publish `conventions.md` in the team's shared knowledge location.
- [ ] Capture a pre-pilot confidence baseline.
- [ ] Collect weekly feedback and log decisions.
- [ ] Review metrics and unresolved critical issues.
- [ ] Document go/no-go decision and rollout scope.

## D. Quality assurance

- [ ] Every rule has a clear trigger, condition, and action.
- [ ] No rule creates an approval bypass.
- [ ] Notifications reach the intended role.
- [ ] Owners and due dates are realistic.
- [ ] A blocked task can be escalated.
- [ ] Declined requests capture a reason and notify the requester.
- [ ] Sensitive information is excluded from general project tasks.
- [ ] All example targets are labeled as targets, not results.
- [ ] Export or capture screenshots of the final configuration for interview evidence.
