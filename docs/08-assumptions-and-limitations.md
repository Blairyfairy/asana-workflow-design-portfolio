# Assumptions and Limitations

## Source materials used

The repository is based on the three supplied rubrics:
- Project 1: Biometric boarding and security.
- Project 2: Project request workflow.
- Project 3: Socialization strategy.

## Missing referenced materials

Project 1 refers to a spreadsheet defining sections and custom fields. Project 2 refers to a process map. Those companion materials were not present among the supplied files. This repository therefore creates a coherent sample design but does not claim exact alignment with unseen spreadsheet or process-map details.

## Illustrative design choices

The following are proposed examples and should be validated:
- Section names and sequence.
- Custom-field names and allowed values.
- Task titles, task descriptions, subtasks, and due dates.
- Dependency links.
- Approval roles and any funding thresholds.
- Form questions and branch logic.
- Automation rules.
- Goals, KPI formulas, and target values.
- Pilot role names, communication timing, and training activities.

## Asana implementation limitations

CSV files are templates for task import and configuration planning. They do not automatically create every Asana-native feature. Depending on plan and workspace configuration, milestones, dependencies, custom fields, rules, forms with branching, approvals, and portfolio reporting may need to be configured manually.

## Security and privacy

The biometric project is intentionally scoped as governance and readiness planning. Do not use this sample as a substitute for a biometric impact assessment, threat model, legal advice, accessibility evaluation, or aviation security approval.

## How to make this production-ready

1. Obtain the missing source spreadsheet and process map.
2. Validate the workflow with process owners and approvers.
3. Replace sample dates and role placeholders.
4. Confirm available Asana features and permissions.
5. Configure the projects in a sandbox.
6. Run test cases and collect pilot evidence.
7. Update the metrics and decision gates using approved organizational policy.
